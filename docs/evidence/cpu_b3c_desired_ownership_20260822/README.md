# CPU-B3C Desired Ownership Evidence

This evidence closes the ambiguity left by demand-origin age. The deterministic
three-logical-CPU route retained one exact desired-ownership snapshot for each
edit-correlated regional publication. Both snapshots had zero open frontend
viewer plans, and every exact replacement member was still visual or collision
required and fully ready.

## Result

- Carve: 4 edit replacements plus 424 non-edit replacements; 125 retirements.
  Publication followed edit replacement readiness by 2987.3597 ms.
- Construct: 1 edit replacement plus 461 non-edit replacements; 184 retirements.
  Publication followed edit replacement readiness by 4289.3048 ms.
- All 428 carve-cohort and 462 construct-cohort replacements were current at
  their latest fully drained frontend viewer-plan boundary.
- Average process use was 1.93 and 1.99 logical cores. Saturated samples were
  16.7% and 18.8%, so this run does not prove three-core CPU exhaustion.
- The route was complete and lossless. Trace-on frame p99 was 33.17325 ms.

The delay is therefore broad, current LOD transition publication work. It is
not proven stale work that can be removed by comparing demand-origin revisions.
The authority's atomic regional publication is preventing partial coverage from
becoming visible while overlapping LOD retirements remain active.

## Remedy ruling

Do not prune members merely because their demand originated in an older viewer
plan. Do not publish an edit replacement independently when it overlaps pending
LOD retirements; that bypasses the coverage rule that prevents terrain openings.

The next bounded A/B candidate is earlier regional coverage prioritization while
the player relocates, before a landed edit is submitted. It must preserve the
same desired set, exact regional membership, and atomic publication contract.
No scheduling or publication behavior was changed by this evidence milestone.

`.godot/world_transvoxel_captures/terrain_waterfall/desired_ownership_*` and are
